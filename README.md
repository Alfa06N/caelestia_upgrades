# caelestia_upgrades

Backup y gestión de mis personalizaciones de [Caelestia](https://github.com/caelestia-dots)
sobre Arch Linux, para que sobrevivan a las actualizaciones del sistema.

## Contenido

| Ruta | Qué es |
|------|--------|
| `files/<subdir>/*.qml` | Los 9 archivos del shell (`caelestia-shell`) que he modificado. |
| `files/config-caelestia/` | Mis configs de usuario (`~/.config/caelestia`: `shell.json`, `monitors/`, `mimeapps.list`, etc.). |
| `files/dots-caelestia/` | Mis personalizaciones sobre los dotfiles de Hyprland (`config-caelestia/*.lua`, `config-hypr/hypridle.conf`, `config-systemd-user/…`, `btop`, `fish`). |
| `files/config-systemd-user/` | Servicios systemd de usuario propios (`caelestia-bt-agent.service`). |
| `files/config-local-bin/` | Scripts propios (`caelestia-bt-agent`, agente BlueZ en Python). |
| `sync-upstream.sh` | Regenera el override del **shell** desde el paquete + reaplica mis parches QML. |
| `sync-dots.sh` | Restaura/guarda mis personalizaciones sobre los **dotfiles de Hyprland** (`--save` para snapshot). |

## Repos relacionados

| Repo | Ruta local | Qué contiene |
|------|-----------|--------------|
| [caelestia_dots](https://github.com/Alfa06N/caelestia_dots) | `~/.local/share/caelestia` (symlink desde `~/.config/hypr`) | Mirror de los dotfiles completos de Caelestia. `origin` = mi repo, `upstream` = oficial. |
| `~/.config/caelestia` | — | Configs de usuario (incl. `hypr-vars.lua`/`hypr-user.lua`); repo git local (sin remoto). |

Para actualizar los dotfiles desde el upstream oficial:

```bash
cd ~/.local/share/caelestia
git fetch upstream
git merge upstream/main   # resolver conflictos si los hay
git push origin main      # subir a mi repo
```

> **Nota (0.56+):** los dotfiles migraron de Hyprland `.conf` (hyprlang) a
> **Lua**. El entry ahora es `hypr/hyprland.lua`; ya no existe `hyprland.conf`
> real (Hyprland regenera un stub de aviso si no encuentra config válido).
> Ver la sección "Migración a Lua" más abajo.

## Por qué es necesario

Quickshell carga el shell desde `<XDG_CONFIG_HOME>/quickshell/caelestia`
(mi override) **con prioridad sobre** `/etc/xdg/quickshell/caelestia` (el
paquete AUR) y **no fusiona** directorios: mi copia reemplaza al paquete por
completo. Si solo copio el paquete una vez, me quedo congelado y no recibo las
novedades.

Este repo resuelve eso: guarda **solo mis diferencias** y regenera la copia
completa a partir del paquete actualizado cuando toque.

```
~/.config/quickshell/caelestia/     <- override activo (copia completa, se regenera)
/etc/xdg/quickshell/caelestia/      <- paquete caelestia-shell (lo actualiza pacman)
~/caelestia_upgrades/files/         <- MIS parches (este repo, versionado)
```

## Flujo tras actualizar el sistema

```bash
sudo pacman -Syu                       # actualiza caelestia-shell, quickshell, hyprland, etc.
~/caelestia_upgrades/sync-upstream.sh  # shell: paquete nuevo + mis parches QML encima
~/caelestia_upgrades/sync-dots.sh      # dots Hyprland: restaura mis personalizaciones .lua
qs -c caelestia kill; sleep 0.6; caelestia shell -d
hyprctl reload
```

Antes de aplicar, se puede probar sin tocar nada:

```bash
~/caelestia_upgrades/sync-upstream.sh --dry-run
~/caelestia_upgrades/sync-dots.sh --dry-run
```

`sync-upstream.sh` hace un backup del override actual en
`~/.config/quickshell/caelestia.bak-<fecha>` antes de regenerarlo.
`sync-dots.sh` hace backup `.bak-<fecha>` de cada personalización que sobrescribe.

### Fusionar si hay conflictos

Si upstream cambió un archivo que yo también modifiqué, el script **sobrescribe
con mi versión** (pierdo la mejora upstream en ese archivo concreto). El script
avisa si alguno de mis parches ya no existe en upstream (renombrado/eliminado).

Para revisar qué cambió upstream en mis archivos:

```bash
# comparar mi parche con el paquete actual
diff ~/caelestia_upgrades/files/services/Nmcli.qml \
     /etc/xdg/quickshell/caelestia/services/Nmcli.qml
```

Y editar `files/...` a mano para integrar la mejora, luego commit + push.

## Migración de Hyprland a Lua (0.56+)

Desde Hyprland 0.55 el lenguaje de configuración pasó de **hyprlang** (`.conf`)
a **Lua**. En los dotfiles de Caelestia 0.56+:

- El entry es `~/.config/hypr/hyprland.lua` (parte del repo de dots).
- Ese entry carga, en orden, `hypr/variables.lua` + `hypr/hyprland/*.lua`, y
  **al final** `require("hypr-user")` y los overrides de `hypr-vars`.
- Ya **no existe** `hyprland.conf` real. Si Hyprland no encuentra un config
  válido, **regenera un `hyprland.conf` stub** (`autogenerated = 1`) con binds
  mínimos y muestra el aviso *"You're using an autogenerated config!"*. Ese stub
  es inofensivo una vez que `hyprland.lua` existe: Hyprland prefiere el `.lua`.

**Mis personalizaciones** (no las toca `caelestia update`):

| Archivo | Contenido |
|---------|-----------|
| `~/.config/caelestia/hypr-vars.lua` | Overrides de variables (apps por defecto, touchpad, `windowBorderSize`, `blurEnabled`, `kbLauncher`…). Se carga **antes** que las configs, así que pisa los valores de `variables.lua`. |
| `~/.config/caelestia/hypr-user.lua` | Monitores, input, envs, window rules y binds personales. Se carga **al final** (gana sobre upstream). |
| `~/.config/hypr/hypridle.conf` | hypridle personalizado (se lanza por servicio systemd, no por Lua). |

Ambos `.lua` los **crea** el entry si no existen (vacíos), así que sobreviven a
las actualizaciones. `sync-dots.sh` los respalda/restaura.

Verificar sintaxis y estado tras un cambio:

```bash
luac -p ~/.config/caelestia/hypr-vars.lua ~/.config/caelestia/hypr-user.lua
hyprctl getoption general:border_size   # p.ej. debe reflejar hypr-vars.lua
hyprctl monitors                        # monitores personalizados
hyprctl reload
```

> **Importante:** `hyprctl reload` recarga el Lua. Pero si la sesión viva
> arrancó con el stub `.conf`, hay que **reiniciar Hyprland** (no basta reload)
> para que tome `hyprland.lua`.

### HyprMod no persiste en la config Lua

HyprMod escribe `~/hypr/hyprland-gui.lua` (y aplica el cambio en caliente con
`hyprctl`), pero **el entry `hyprland.lua` no carga ese archivo**, así que los
cambios de HyprMod **se pierden al reiniciar**. Solución: llevar los ajustes a
`~/.config/caelestia/hypr-vars.lua` (que sí se carga siempre). Ejemplo:

```lua
return {
    windowBorderSize = 2,
    blurEnabled      = false,
}
```

`hyprland-gui.lua`/`hyprland-gui.conf` quedan ignorados (inofensivos).

## Personalizaciones de Hyprland: por qué están a salvo

- `hypr-vars.lua` y `hypr-user.lua` viven en `~/.config/caelestia/`, que **no
  pertenece al repo de dots** y por tanto no lo toca `caelestia update` ni
  pacman. Se guardan aquí como respaldo (`files/dots-caelestia/config-caelestia/`).
- El entry oficial `hypr/hyprland.lua` (en el repo de dots) se dejó **idéntico a
  upstream** para que `git merge upstream/main` no dé conflictos.
- `fix_lag.sh` (Escritorio) quedó **deshabilitado** (`fix_lag.sh.disabled`): con
  power-profiles-daemon ya no hace falta forzar el nivel de la GPU.

## Archivos del shell personalizados

- `services/Nmcli.qml` — `forgetNetwork` por SSID (soporta perfiles duplicados), callbacks de resultado.
- `services/Notifs.qml` — limpieza O(n) y tope de notificaciones persistidas.
- `services/Wallpapers.qml` — debounce del preview de color y del fondo.
- `utils/NetworkConnection.qml` — fixes del flujo de conexión WiFi.
- `modules/bar/popouts/Network.qml` — prompt de contraseña para redes sin PSK.
- `modules/bar/popouts/WirelessPassword.qml` — cierre inmediato al conectar (fix "Connecting...").
- `modules/nexus/pages/network/NetworkDetailPage.qml` — estado de error al "Forget".
- `modules/nexus/pages/network/AddNetworkPage.qml` — callbacks de limpieza.
- `modules/sidebar/NotifDock.qml` — limpieza masiva de notificaciones.
- `modules/nexus/pages/bluetooth/BluetoothPairing.qml` — conexión + `trusted` automático tras emparejar (con fallback).

## Gestión de energía (perfiles)

Los botones de "Modos de Rendimiento" del shell usan `Quickshell.Services.UPower`
→ **power-profiles-daemon** (ppd) por D-Bus. Por eso **TLP se desactivó** (ambos
no pueden coexistir: pelean por `platform_profile` y los governors).

Estado actual del sistema (no versionado, es config de root):

```bash
sudo systemctl disable --now tlp                 # TLP apagado
sudo systemctl unmask power-profiles-daemon
sudo systemctl enable --now power-profiles-daemon
powerprofilesctl list                            # performance/balanced/power-saver
```

Respaldo local: `~/tlp.conf.bak-<fecha>` y `~/tlp-migration.log`.

Revertir (si hiciera falta):

```bash
sudo systemctl disable --now power-profiles-daemon
sudo systemctl enable --now tlp
sudo cp ~/tlp.conf.bak-<fecha> /etc/tlp.conf
```

## Agente Bluetooth

`caelestia-bt-agent` (Python/dbus, capacidad `NoInputNoOutput`) permite emparejar
dispositivos "just works" desde la GUI de Caelestia, que no trae agente propio.
Se instala como servicio systemd de usuario (`caelestia-bt-agent.service`), se
habilita en el login y `sync-upstream.sh` lo reinstala. Cero dependencias nuevas
(usa `python-dbus`/`python-gobject` ya presentes).

Al confirmar el emparejamiento, el agente escribe `Trusted=true` vía D-Bus, así
los dispositivos reconectan solos sin marcarlos a mano.

## Bluetooth: evitar desconexiones en reposo (Opcion C)

Sintoma: el teclado/raton se "desconectaban" a los ~20s de inactividad y
reconectaban al usarlos. Dos causas:

1. **Autosuspend del radio USB.** El adaptador Realtek `0bda:c123` tenia
   `power/control = auto` con `autosuspend_delay_ms = 2000` (2s), y
   `btusb enable_autosuspend=Y`. En reposo el stack USB suspendia el radio y
   cortaba el enlace.

   Fix por regla udev `files/etc-udev/50-bluetooth-no-autosuspend.rules`:

   ```bash
   sudo install -m 644 files/etc-udev/50-bluetooth-no-autosuspend.rules \
        /etc/udev/rules.d/50-bluetooth-no-autosuspend.rules
   sudo udevadm control --reload-rules
   sudo udevadm trigger --action=add --subsystem-match=usb
   cat /sys/bus/usb/devices/1-2/power/control   # -> on
   ```

2. **Cierre por inactividad de BlueZ.** `IdleTimeout` sin fijar. Se pone a `0`
   (nunca cerrar enlaces) en `/etc/bluetooth/main.conf` bajo `[General]`:

   ```bash
   sudo cp -a /etc/bluetooth/main.conf /etc/bluetooth/main.conf.bak-$(date +%F-%H%M%S)
   sudo sed -i '/^\[General\]/a IdleTimeout = 0' /etc/bluetooth/main.conf
   sudo systemctl restart bluetooth
   ```

`sync-upstream.sh` aplica ambos si hay sudo disponible (o imprime los comandos
a mano). Ver `files/etc-bluetooth/main.conf.README`.

## Gestor de archivos: Thunar como predeterminado

Dos mecanismos distintos, ambos necesarios:

1. **MIME `inode/directory`.** El default estaba en `kitty-open.desktop` (la
   terminal), y Dolphin aparecia por ser KDE. Se fija en
   `~/.config/mimeapps.list`:

   ```
   [Default Applications]
   inode/directory=thunar.desktop

   [Added Associations]
   inode/directory=thunar.desktop;
   ```

   Aplica a Telegram (Qt), `xdg-open`, links `file://`, etc.

2. **D-Bus `org.freedesktop.FileManager1`.** Chromium/Brave NO usa MIME para
   "Mostrar en carpeta": llama a este nombre por D-Bus. Dos paquetes lo
   reclaman (`dolphin --daemon` y `Thunar --gapplication-service`); ganaba
   Dolphin.

   El bus usa **dbus-broker**, que solo busca servicios en `XDG_DATA_DIRS`
   (`/usr/local/share:/usr/share`) y **no** lee `~/.local/share`. Por eso el
   override va a `/usr/local/share/dbus-1/services/` (mayor prioridad que
   `/usr/share`, pacman no lo toca):

   ```bash
   sudo install -D -m 644 files/usr-local-share/dbus-1/services/org.freedesktop.FileManager1.service \
        /usr/local/share/dbus-1/services/org.freedesktop.FileManager1.service
   systemctl --user restart dbus-broker
   ```

   Notas:
   - Requiere **reiniciar el broker** (o cerrar sesion) para recargar servicios.
   - El "Guardar archivo" de Brave usa el **portal** `FileChooser` (gtk): es lo
     correcto, no se toca.
   - El dialogo "Save Image" de Telegram es propio de Telegram, no configurable.

`sync-upstream.sh` instala ambos si hay sudo. Dolphin se **conserva** instalado
(solo se le quita la prioridad en FileManager1).

## Restaurar desde cero (equipo nuevo)

```bash
git clone https://github.com/Alfa06N/caelestia_upgrades.git ~/caelestia_upgrades
sudo pacman -S caelestia-shell caelestia-cli caelestia-meta quickshell-git hyprland
~/caelestia_upgrades/sync-upstream.sh   # shell
~/caelestia_upgrades/sync-dots.sh       # personalizaciones Hyprland (.lua, hypridle, btop, fish)
cp -a ~/caelestia_upgrades/files/config-caelestia/. ~/.config/caelestia/
qs -c caelestia kill; sleep 0.6; caelestia shell -d
hyprctl reload
```

> Los dotfiles base de Hyprland (`~/.local/share/caelestia`) se instalan con
> `caelestia install` / `caelestia update` (ver `manifest.toml`); ya no hay
> `install.fish`. `sync-dots.sh` solo restaura las personalizaciones encima.
